# MR 촬영 환경 만들기

**무엇**: 헤드셋을 쓸 방을 어떻게 꾸며야 MR이 잘 보이는가. 천·조명·바닥을 어디에 어떻게 쓰는지와, **바꾸기 전후를
수치로 재는 법**이다.

**왜 따로 있나**: 근거는 `Varjo-Capabilities.md` 여기저기(§3 occlusion 환경, §11 조명·트래킹 평가)에 흩어져 있어서,
실제로 방을 꾸밀 때 한 장으로 보기 어려웠다. 이 문서는 **그 원문들을 실행 순서로 묶은 것**이고, 사실관계가
다르면 `Varjo-Capabilities.md`가 기준이다.

---

## 0. 결론부터

1. **방 전체를 검정으로 덮지 마라.** 트래킹이 죽는다
2. 검정 무광 천은 **차 바로 뒤 배경에만**
3. **천보다 조명이 효과가 크다** — 1000 lux 내외, 한 가지 색온도, 디퓨즈
4. 바꿨으면 **Varjo Base의 tracking environment evaluation으로 재라.** 주관으로 판단하지 마라

---

## 1. ⚠️ 검정 천의 함정 — 요구가 서로 충돌한다

검정 무광 천은 **가상 물체가 또렷이 보이게** 하는 데는 맞다. 그런데 같은 헤드셋의 다른 기능들이 정반대를 원한다.

| 무엇이 | 무엇을 원하나 |
|---|---|
| **inside-out 트래킹** | **텍스처가 있는 표면.** 밋밋하면 Yellow/Red — 원문: *"Add items like furniture, posters, or decorations"* |
| **depth occlusion**(T/U) | matte **white** 선호. **검고 어두운 재질은 회피**. 거울·유리·광택도 회피 |
| **패스스루 화질** | **1000 lux 내외.** 어두우면 카메라 노이즈가 늘고 성능까지 떨어진다 |
| **가상 물체 대비** | 어둡고 무광인 배경 ← **여기만 검정을 원한다** |

**그래서 검정은 "카메라에 찍히지만 추적에는 안 쓰이는 면"에만 쓴다.** 방 전체를 검정 벨벳으로 싸면
헤드셋이 붙잡을 특징이 사라져 트래킹이 흔들리고, 마커 캘리브레이션도 같이 나빠진다.

### 패스스루 밝기 기준 (lux)

| lux | 판정 |
|---|---|
| 1100 | Perfect |
| 400 | Good |
| 260 | Acceptable |
| 160 | 노이즈 보이나 헤드셋에선 수용 가능 |
| 110 | 노이즈 + **성능 저하** |
| < 50 | 매우 noisy, 성능 나쁨 |

## 2. 어디에 무엇을 쓰나

| 위치 | 권장 | 왜 |
|---|---|---|
| **clay·차 바로 뒤 배경** | 무광 검정 몰톤·벨벳 ✅ | 천이 제값 하는 유일한 곳. 실제 잡동사니가 가상 차 뒤에서 어른거리지 않는다 |
| **바닥** | **무광 중간 회색**. 검정 광택 바닥 금지 | 반사면은 캘리브레이션 드리프트의 주 원인이다(`Headset-Test-Checklist.md` §드리프트) |
| **먼 벽·천장** | **덮지 말 것.** 포스터·가구·배관 같은 특징을 남긴다 | 트래킹이 붙잡을 것이 필요하다 |
| **물리 buck·박스·의자** | **무광 처리**(무광 스프레이·매트 도장) | 원문 결론: *"무광 처리가 최고 가성비 투자"* |
| **창문** | 암막 | 자연광은 시간에 따라 색온도가 변해 셋업을 망친다 |
| **손 뒤쪽** | 피부색과 뚜렷이 다른 색 + 뒤의 밝은 디스플레이 끄기 | 손 추적 품질 |

**거울·유리·광택 금속**은 치우거나 무광 테이프로 덮는다. depth 추정과 트래킹 양쪽에 나쁘다.

---

## 3. 천 말고 다른 수단

1. **무광 검정 도장** — 고정 구조물은 천보다 낫다(주름·먼지·처짐이 없다). 무대용 흑색 도료 계열
2. **조명이 천보다 효과가 크다** ← 여기에 먼저 투자한다
   - **색온도 3000–6500K, 한 가지로 통일.** 색온도가 다른 등을 섞지 않는다
   - **LED 또는 인버터 형광등**(플리커 방지). **>1kHz 최적**. 50/60Hz는 flicker compensation과 함께면 허용
   - **스포트라이트보다 디퓨즈·간접 조명.** 사용자가 광원을 직접 보지 않게 배치
   - 카메라 **auto white balance를 잠근다**. 렌더 노출은 튜닝 창 `Display → Exposure compensation`으로 맞춘다
3. **소프트웨어로 지우기 — UE 알파 마스크** (`Varjo-Capabilities.md` §4-1, `Operating-Guide.md` §5 Mask Mesh)
   - Custom Depth 마스크 메쉬로 특정 영역만 패스스루로 뚫는다. **depth estimation을 쓰지 않으므로 반사면 노이즈와 무관** —
     천으로 못 가리는 곳의 대안이다
4. **크로마키는 권하지 않는다** — Unreal에서는 Varjo Base 경유만 되고, **depth occlusion과 동시 사용 불가**인데
   **API가 막아 주지도 않는다.** 쓸 거라면 마스킹 면은 *무광 fabric + 고채도 순색*이다

---

## 4. ★ 주관 말고 수치로 — tracking environment evaluation

**Varjo Base > More > Analytics window > Performance > tracking environment evaluation > Show**

헤드셋을 **실제 사용 중 볼 방향들**(스크린·벽·천장)로 **천천히** 돌린다.

| 결과 | 의미 |
|---|---|
| **Green** | *"Your current view is optimal for inside-out tracking"* |
| **Yellow** | *"Tracking is degraded but not yet lost"* |
| **Red** | *"Tracking is lost"* |

**Yellow/Red 원인**: 텍스처 있는 표면 부족 / 조명 부적절 / **헤드셋 전면판이 벽에 너무 가까움** /
움직이는 것이 너무 많이 보임 / 헤드셋 급속 이동.

**천을 치기 전과 후에 한 번씩** 돌려 결과를 적어 두면 "좋아 보인다"가 아니라 판정으로 남는다.
환경을 바꿨으면 **Room Setup을 다시 실행**한다.

---

## 5. 손 추적이 잘 되게

포트 판정(`Headset-Test-Checklist.md` §12)은 손 추적 품질을 넘을 수 없다.

- 손 뒤 배경에 **손과 색이 뚜렷이 다른 물체**를 둔다
- 손 뒤의 디스플레이·조명을 낮춘다
- **장갑·장신구·시계·밝은 매니큐어를 뺀다**(문신도 품질에 영향을 줄 수 있다)
- Varjo Base의 hand tracking을 `Automatic` 또는 `Varjo hand tracking`으로

---

## 6. 방을 꾸미는 순서

1. 창문 암막 → 외부광 차단
2. 조명 통일(색온도 하나, LED, 디퓨즈·간접) → **1000 lux 내외** 확보
3. **tracking environment evaluation 1차** 측정, 결과 기록
4. 거울·유리·광택 제거 또는 무광 처리
5. **차 뒤 배경에만** 검정 무광 천
6. 먼 벽·천장의 특징은 **남긴다**(여기서 Yellow가 뜨면 포스터·가구를 더한다)
7. **tracking environment evaluation 2차** 측정 → 1차와 비교
8. **Room Setup 재실행**
9. 마커 배치 → `Headset-Test-Checklist.md`의 캘리브레이션 절차

---

## 아직 안 한 것

- 이 방의 실제 lux 측정값이 없다. 조도계로 재서 §1 표와 비교해 적어 둘 것
- tracking environment evaluation 결과(전/후)를 아직 기록하지 않았다
- 무광 처리의 효과를 드리프트 수치(`Headset-Test-Checklist.md` §드리프트)로 확인하지 않았다
