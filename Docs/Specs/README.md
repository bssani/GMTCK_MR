# 작업 명세

Claude가 쓰고 Codex가 구현하는 작업 단위다. 파일 하나가 브랜치 하나(`codex/<파일 이름>`)다. 규칙은 [AGENTS.md](../../AGENTS.md), 흐름은 [Agent-Workflow §1](../Agent-Workflow.md#1-역할과-흐름).

파일 이름: `<짧은-영문-이름>.md` (예: `dynamic-object-follow.md`). 리뷰는 같은 이름으로 [Docs/Reviews/](../Reviews/)에 남는다.

## 틀

```markdown
# <제목>

- 베이스 브랜치: `main` | `project/<이름>`
- 상태: 작성 중 | 구현 대기 | 리뷰 중 | 머지함 (<커밋>)

## 목적
무엇을 왜 만드는가. 쓰는 사람(진행자·착용자)과 상황.

## 범위
만들 것. 에디터 작업(레벨·Blueprint·애셋 값)이 있으면 Codex 몫인지 사용자 몫인지 적는다.

## 범위 밖
하지 않을 것.

## 지켜야 할 조건
바꾸면 안 되는 것: 저장 형식, 기존 조작 키, `/CXMR/` 기본값, 기존 시험.

## 근거
쓸 Varjo·엔진 API와 확인한 소스(경로:줄). 관련 문서 절.

## 구현자가 정할 것
Codex 재량인 항목. 여기 없는 것은 질문한다.

## 경계 상황
요구마다: 마커가 한 프레임 끊김, 손 추적 손실, 차량 교체 중 입력, 세션이 아직 없음 등과 그 시험.

## 완료 조건
번호를 붙인다. 보고 ②에서 하나씩 답한다.

## 로컬에서 확인할 것
빌드, 자동화 시험(접두어), 에디터 확인, 헤드셋 시험(Headset-Test-Checklist 절).

## 개정 이력
- YYYY-MM-DD: 처음 작성
```
