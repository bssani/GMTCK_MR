# 움직이는 실물 따라가기 — 박스

- 베이스 브랜치: `main`
- 상태: 구현 대기 — [control-window.md](control-window.md)가 `main`에 머지된 뒤 시작한다. 켜기·끄기 자리가 그 창에 있다. 아래 "열린 질문" Q1은 헤드셋 확인 뒤 Claude가 채운다.

## 목적

사용자 결정(2026-10-14):

- 실물 박스에 Varjo 마커를 붙이고, 가상 박스가 실물 박스를 따라 움직이게 한다.
- 진행자가 물체마다 따라가기를 켜고 끌 수 있다.
- 설정 방법을 문서로 안내한다.

지금 있는 것과 없는 것:

- 있음: Varjo 런타임의 마커별 Dynamic 모드 설정(`UCXMRSubsystem::SetMarkerTrackingMode`, `SetMarkerTimeout`, `CXMRSubsystem.h:168-169`), 마커 역할 값 `ECXMRMarkerRole::DynamicObject`와 `TargetTag`(`CXMRTypes.h:17`, `:123-124`).
- **없음**: 가상 물체를 마커에 맞춰 움직이는 코드. 위 역할 값과 `TargetTag`를 읽는 곳이 없다.

## 설계 결정 (Claude, 사용자 확인 2026-10-14)

- **물체가 스스로 선언한다.** 가상 박스 액터에 새 컴포넌트(이름은 구현자가 정함, 예: `UCXMRTrackedObjectComponent`)를 붙이고, 그 컴포넌트가 자기 마커 목록을 가진다.
  - 차량 마커 프로필의 `DynamicObject` 역할과 `TargetTag`는 쓰지 않는다. 박스는 차량을 바꿔도 그대로인 장면 물체라서, 차량 프로필에 두면 차량마다 다시 적어야 한다.
  - VR 전용·마스크 오브젝트를 컴포넌트로 선언하는 지금 방식(`UCXMRSceneObjectComponent`)과 같은 원칙이다.
  - 두 값은 지우지 않고 툴팁에 "쓰지 않음, 물체 컴포넌트를 쓸 것"이라고 적는다. 저장된 애셋 값이 깨지지 않게 하려는 것이다.
- **한 물체에 마커 여러 개.** 박스를 손에 들면 한 면이 가려지기 쉬워서, 면마다 마커를 붙이는 것을 기본으로 한다.
  - 지금 관측 중인 마커(보정 마커와 같은 0.5초 기준)마다 물체 위치 후보를 만든다.
  - 후보가 여럿이면 평균한다. 위치는 평균, 방향은 forward·up 벡터 평균이다(`AccumulateSample`/`FMarkerSamples::Mean`, `CXMRPlacementComponent.cpp:318-351`과 같은 방식).
- **마커 위치는 면으로 정한다.** 마커마다 다음을 지정한다.
  - 박스의 어느 면 가운데에 붙였는지: Top·Bottom·Front·Back·Left·Right·Custom
  - 그 면 안에서 몇 도 돌려 붙였는지: 0·90·180·270
  - 박스 크기는 컴포넌트 값으로 받는다.
  - Custom이면 마커의 물체 기준 Transform을 직접 넣는다.
  - 사람이 Transform을 손으로 재서 넣으면 틀리기 쉬워서 이 방식을 기본으로 한다.
- **추적 모드.**
  - 물체 마커에는 고급 창 `Objects.TrackingMode`(기본 Dynamic)를 적용한다. 보정 마커는 늘 Stationary다(U-1 정확도).
  - Varjo의 모드·timeout 설정은 마커가 처음 감지된 뒤에만 성공한다(`Docs/Varjo-Capabilities.md` §5-2 3번). 그래서 처음 관측될 때 설정하고, 실패하면 다음 관측 때 다시 시도한다. Placement의 `ConfiguredMarkerIds` 방식(`CXMRPlacementComponent.cpp:261-270`)을 참고한다.
- **켜기·끄기는 물체마다 한다.** 끄면 가상 물체는 그 자리에 멈춘다. 켜면 다음 관측부터 다시 따라간다.
- **마커를 놓쳤을 때**는 고급 창 `Objects.WhenLost`를 따른다: Hold last position(기본) / Hide. 다시 보이면 따라가고, Hide였으면 다시 보이게 한다.
- **떨림 줄이기는 이번에 넣지 않는다.** Dynamic 값을 그대로 써서 지연을 가장 작게 한다. 헤드셋 결과를 보고 다음에 정한다.

## 범위

1. 물체 컴포넌트: 마커 목록(ID·면·면 안 회전·Custom Transform), 박스 크기, 켜짐 여부, 이름(창에 표시)
2. 마커 이벤트(감지·이동·놓침)를 받아 물체 위치를 계산하고 액터를 옮긴다. 액터의 루트를 옮기므로 가상 박스 메시는 그 자식이다.
3. 고급 창 Calibration 탭 "Moving objects" 묶음의 두 행(`Objects.TrackingMode`, `Objects.WhenLost`). 문구·기본값은 시안 `SETTINGS`다.
4. 기본 창 Scene 탭 "Moving objects" 목록: 물체마다 스위치, 이름, 마커 ID, 상태 문구. 문구는 시안 `renderObjects()` 그대로다.
5. 다른 기능과의 경계:
   - 같은 마커 ID가 차량 보정 마커와 물체 마커에 둘 다 있으면 경고하고 물체 쪽을 무시한다.
   - 물체 마커는 U-1 "필요 마커"에 들어가지 않는다.
   - 물체 마커는 `CXMR.DumpMarkers` 로그에는 나온다.
6. 시험용 박스 애셋을 만든다(아래 "에디터 작업"). 레벨 `/Game/Map/L_Main`에 하나 둔다.
7. 문서: `Docs/Operating-Guide.md`에 "움직이는 실물(박스) 설정" 절, `Docs/Headset-Test-Checklist.md`에 박스 시험 절. 담을 내용은 아래 "안내 문서에 넣을 것".

### 에디터 작업 (Codex, 에디터 MCP)

- `/Game/Objects/BP_TrackedBox` — 루트 + 박스 메시(엔진 기본 큐브를 박스 크기로) + 물체 컴포넌트. 예시 값은 박스 30×30×30 cm, 마커 ID 21(Top)·22(Front)다. 실제 박스 치수와 ID는 사용자가 바꾼다.
- `/Game/Map/L_Main`에 하나 배치한다. 차량 앞 바닥 위, 차와 겹치지 않는 곳이면 된다.
- 규칙은 [Agent-Workflow §3](../Agent-Workflow.md#3-에디터-mcp)을 따른다. 저장 → 스크린샷 → 에디터 닫기.

## 범위 밖

- 문·뚜껑처럼 경첩에 묶인 1축 물체
- Vive Tracker 출처. 헤드셋 PC 로그에 `XR_HTCX_vive_tracker_interaction`이 있으면 다음 명세에서 같은 컴포넌트에 출처를 더한다. 이번 구현은 출처를 바꿔 끼울 자리를 일부러 만들지 않는다.
- 떨림 줄이기, 예측 보정
- 물체 마커 위치를 자동으로 학습하는 기능

## 지켜야 할 조건

- 차량 보정·저장·복원 동작은 바뀌지 않는다. 보정 마커의 추적 모드는 Stationary 그대로다.
- 물체가 없는 레벨에서는 아무 일도 하지 않는다. 창의 Moving objects 목록은 "No moving objects in this level."(시안 말투) 한 줄만 보인다.
- 세션 전에 Varjo 함수를 부르지 않는다(AGENTS.md).
- `/CXMR/` 애셋은 바꾸지 않는다. 새 애셋은 `/Game/Objects/`에만 만든다.

## 근거

- 마커 이벤트 구독·관측 판정: `CXMRPlacementComponent.cpp:164-237`
- 마커 이벤트 좌표는 이미 월드 좌표다(`Docs/Varjo-Capabilities.md` §5-1). 놓침 이벤트에는 위치가 없다. 감지 이벤트는 세션당 ID마다 한 번이고, 그 뒤로는 이동 이벤트로 온다(§5-2 1번).
- 선언형 컴포넌트 선례: `UCXMRSceneObjectComponent`
- Dynamic 모드: Varjo 문서 "Dynamic mode gives more responsive pose updates", 예측을 켜면 정확도가 떨어진다(§5-3).

## 열린 질문

- **Q1 마커 좌표축.** Varjo 마커 포즈에서 어느 축이 마커 면 밖(법선)을 향하고, 어느 축이 인쇄된 마커의 "위"를 향하는지 기록이 없다. 면 → Transform 계산이 여기에 달려 있다. 사용자가 2026-10-15 헤드셋 시험에서 마커 축 표시로 확인한다(체크리스트 §15-4). Claude가 결과를 여기에 적기 전에는 면 계산 시험의 기대값을 확정할 수 없다. 그 전에 구현이 여기까지 오면 질문하고 멈춘다.

## 구현자가 정할 것

- 컴포넌트·프로퍼티 이름, 면 계산 코드 구조
- 후보가 여러 개일 때 평균에서 크게 벗어난 후보를 빼는 기준. 넣는다면 cm 값을 프로퍼티로 두고 보고 ③에 적는다.

## 경계 상황

- 박스를 돌려 위 면 마커가 가려지고 옆면 마커만 보임 → 옆면 마커로 계속 따라가고, 바뀌는 순간 튀지 않는다. 시험은 두 마커의 후보가 같을 때 위치가 그대로인지로 한다.
- 두 마커 후보가 크게 다름(박스 크기·면 설정이 틀림) → 평균이 튄다. 경고 로그에 마커별 후보를 남긴다.
- 마커가 0.5초 넘게 끊겼다 다시 보임 → Hold면 그 자리에서 이어 가고, Hide면 다시 나타난다.
- 진행자가 따라가기를 끔 → 그 자리에 멈춘다. 마커 이벤트는 계속 들어오지만 움직이지 않는다. 다시 켜면 다음 관측 위치로 바로 간다.
- 마커 추적 전체를 끔(고급 창 Diagnostics) → 물체는 Hold/Hide 규칙대로 한다.
- 레벨에 물체 컴포넌트가 둘 이상 → 각자 독립이다. 같은 마커 ID를 두 물체가 쓰면 경고하고 먼저 등록된 쪽만 쓴다.

## 안내 문서에 넣을 것

`Docs/Operating-Guide.md`의 "움직이는 실물(박스) 설정" 절이다. Codex가 쓰고 Claude가 리뷰한다.

1. **마커 준비.** Varjo 마커를 인쇄해 박스의 평평한 면 가운데에 붙인다. 마커가 클수록 멀리서 잡힌다. 휘거나 들뜨면 위치가 흔들린다. 면마다 다른 ID를 쓰고, 차량 보정 마커와 같은 ID를 쓰지 않는다.
2. **가상 박스.** `BP_TrackedBox`를 복제해 박스 치수와 마커 목록(ID·면·면 안 회전)을 넣는다. 레벨에 놓는다.
3. **확인.** 고급 창 Diagnostics에서 "Marker axes and labels"를 켜고 박스를 들어 본다. 가상 박스가 실물에 겹치는지 본다. 면 안 회전이 틀리면 박스가 90°씩 돌아 있으니 그 값을 고친다.
4. **켜고 끄기.** 기본 창 Scene 탭 Moving objects의 스위치로 한다.
5. **잘 따라오게 하는 법.**
   - 박스를 들 때 손이 마커를 덮지 않게 모서리를 잡는다.
   - 마커가 헤드셋 카메라 시야 안에 있어야 한다. 고개를 돌리면 놓친다.
   - 너무 빨리 흔들면 늦게 따라온다.
6. **깊이와 겹칠 때.**
   - 깊이 테스트가 켜져 있으면, 깊이 범위(기본 0.75 m) 안의 실물 박스가 가상 박스를 가리거나 둘이 겹친 면이 깜빡일 수 있다.
   - 가상 박스를 실물보다 사방 1~2 cm 크게 만들면 가상 면이 늘 앞에 있어 덜 깜빡인다.
   - 그래도 깜빡이면 고급 창 MR 탭의 Depth range far를 줄인다. 그러면 손이 차 앞에 보이는 거리도 같이 줄어든다.

## 완료 조건

1. 합성 마커 이벤트로 시험(헤드셋 없이):
   - 마커 하나로 물체 위치 계산
   - 마커 둘의 평균
   - 놓침 뒤 Hold·Hide
   - 끄기·켜기
   - 보정 마커와 ID 충돌 경고
   - 물체 마커가 U-1 필요 마커 수에 안 들어감
2. 면 계산 시험: Q1이 채워진 뒤의 축 규칙으로, 면·회전마다 물체 위치가 맞다.
3. 창: Scene 탭 목록과 고급 창 두 행을 렌더해 `Saved/ControlWindowPreview_Objects*.png`로 남긴다.
4. `BP_TrackedBox`와 `L_Main` 배치: 스크린샷, 보고 ①에 경로.
5. `-DisableAdaptiveUnity` 빌드 경고·오류 0, `CXMR.` 전체 통과.
6. 문서 두 곳.
