1. R1-1 정렬 저장을 캡처 동안의 평균으로

- 새 기능, 패널 레이아웃 변경, 애셋(`.uasset`·`.umap`) 변경

## 지켜야 할 조건

- **저장 파일 형식을 바꾸지 않는다.** 필드(`alignmentVersion` 1, `alignmentMarkers`, `primaryMarker`, `markers[]`의 `id`·`x`…`roll`, `vehicleProfile`·`vehicleOffset`·`vehicleClass`, 그룹 식별 정보)와 경로가 그대로여야 한다. 지금 있는 저장 파일이 수정 뒤에도 같은 결과로 읽혀야 한다.
- 파일을 거부하는 조건(R1-3)은 바꾸지 않는다. 안내만 더한다.
- 보정 중 평균(`MarkerSamples`, `bAverageMarkerSamples`)의 동작은 그대로다. R1-1은 캡처 전용으로 따로 쌓는다.
- freeze 모드(`bFreezeAfterCalibration=true`, 기본값)의 동작은 그대로다.
- 조작 키와 기존 패널 문구는 그대로다. 새 안내 문구만 더한다. UI 문구는 영어로 쓴다.
- 기존 `CXMR.` 시험 78개는 그대로 통과해야 한다. 기대값을 바꿔야 하는 시험이 있으면 보고 ③에 이유를 적는다.

## 구현자가 정할 것

- R1-1: 마커당 최소 표본 수의 기본값과 프로퍼티 이름. 평균 계산은 기존 `AccumulateSample` 방식(위치 평균 + 회전 평균)을 따른다.
- R1-2: 캐시 무효화 조건의 세부(월드 비교, 소유자 파괴 확인).
- R1-3: 안내 문구와 사유 구분 방식(enum이든 문구 분기든).

## 경계 상황

- R1-1: 캡처 중 한 마커만 표본이 적음 → 저장 거부 + 몇 개 더 필요한지 안내. 캡처 중 마커가 0.5초 넘게 끊김(H-1의 관측 만료) → 그 마커의 캡처 표본을 버리고 다시 쌓음. 캡처 중 차량 교체·차 이동 → 지금처럼 취소되고 표본도 비워짐.
- R1-2: PIE를 다시 시작함, 차량 액터를 다시 로드함, Placement 액터가 파괴됨 → 캐시가 무효화되고 다시 찾음.
- R1-3: 사유가 겹침(모델 변경 + 마커 추가) → 하나 이상 보이면 된다. 순서는 구현자가 정한다. 저장 파일이 없음 → 지금처럼 메시지 없음(차량별), 그룹이면 기존 `NoGroupSave` 그대로.
- R1-4: 캡처가 저장으로 끝남 → 잠금 유지. 캡처가 취소됨 → 시작 전 상태로. 시작 전부터 잠겨 있었음(복원·수동 정렬) → 취소해도 잠금 유지.

1. R1-1 ~ R1-4가 리뷰 파일의 "문제"를 해결하고, 각 항목 상태가 `반영함 (<커밋 제목>)`이다.
2. 리뷰 파일의 "확인할 시험"이 자동화 시험으로 들어가 있고 통과한다.
3. `-DisableAdaptiveUnity` 빌드 성공, CXMR·GMTCK_MR 모듈 경고·오류 0.
4. `CXMR.` 전체 통과.
5. 바이너리 애셋 변경 0(`git status`에 `.uasset`·`.umap` 없음).
